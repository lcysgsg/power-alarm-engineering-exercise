# 业务说明：模拟电力设备告警

本项目采用简化的电力设备遥信告警模型。示例站点、设备名称和事件为虚构数据；不实现电力通信规约。

## 术语

| 术语 | 含义 |
| --- | --- |
| 事件（source event） | 上游设备系统发送的一条业务通知，有来源 ID、事件 ID、信号编码和发生时间 |
| 告警实例（alarm occurrence） | 某信号的一次告警发生及其后续恢复、人工确认记录 |
| 告警发生（RAISED） | 某信号进入异常条件；创建一条告警实例 |
| 告警恢复（CLEARED） | 某信号的异常条件结束；更新相应未恢复的告警实例 |
| 人工确认（acknowledge） | 运行人员已知悉这条告警，不代表现场异常已消除 |

## 本题采用的规则

1. `active=true` 表示当前尚未收到该告警实例的恢复事件；`active=false` 表示已恢复。
2. `acknowledgedAt=null` 表示未确认。确认人和首次确认时间只记录一次。
3. 人工确认与告警恢复是两个独立维度：可以“告警中且已确认”，也可以“已恢复但未确认”。
4. `sourceId + eventId` 唯一标识一条上游事件。同一个来源可以重新发送相同事件；相同 ID 的重试不能重复生效。
5. 不同来源允许使用相同 `eventId`；同一来源的不同 `eventId` 为不同事件。
6. 当前模拟数据按照事件发生顺序发送。事件乱序与复杂关联策略不属于必做任务。
7. 当前业务仅使用 `sourceId + signalCode` 关联恢复事件与未恢复的告警实例。一个信号在未恢复期间不会再次产生另一条合法的 RAISED 事件。
8. 上游事件的 `occurredAt` 是事件发生时间，不等同于平台接收时间；人工确认时间由平台生成。

## 学习与判断

不要求候选人熟悉 IEC 104、IEC 61850 等规约。请依据此页的业务约定实现和验证，遇到未定义情形可做合理假设并在交流时说明。
